# Baseline поиска — 29 октября 2026

Измерены **42 последовательных поиска: 21 локально и 21 на Vercel Preview**.
Это предварительный замер на **трёх EAN, по семь повторений**, а не золотой набор
из 20 SKU: данные владельца для него ещё не предоставлены.

На Vercel запросы завершались быстрее, но давали меньше точных кандидатов:
отказы магазинов и короткие пропуски circuit breaker сокращали время работы.
Эти числа нельзя трактовать как ускорение качественного поиска.

## HTTP 403 и timeout

Прямой probe обращается к каждому источнику по всем трём EAN без кэша и
circuit breaker; он показывает HTTP-ответ именно с IP среды запуска.

| Источник      | HTTP 403 локально, из 3 EAN | HTTP 403 Vercel, из 3 EAN |
| ------------- | --------------------------: | ------------------------: |
| METRO Moldova |                           0 |                         3 |
| Bonus Moldova |                           0 |                         3 |
| Linella       |                           3 |                         3 |

У остальных источников probe HTTP 403 не наблюдался. Таймаутов в обоих probe
не было. Общее время probe: **20511 мс локально**, **20402 мс на Vercel**.
SearXNG не настроен в обеих средах; Tavily `/usage` доступен локально и не настроен
в Preview. Проверка `/usage` не выполняет поиск.

В серии поиска SKU отдельно зарегистрирован **один локальный timeout Состависты**:
EAN `3017620422003`, повтор 4, шаг **18354 мс**, весь поиск **18823 мс**.
Остальные источники в серии не получили статус `timeout`; на Vercel таких статусов
не было. Время шага не равно лимиту отдельного HTTP-запроса: оно включает фазы
DNS/HTTP и ожидания ограничения частоты; этот замер не разделяет их вклад.

В диагностике SKU зафиксированы два HTTP 403 Linella локально и по два HTTP 403
METRO/Linella на Vercel. **Ноль записей 403 Bonus в серии SKU не означает доступность**:
METRO и Bonus используют общий хост, и после отказа METRO Bonus пропускался
действующей паузой. Прямой probe подтвердил его HTTP 403 для всех трёх EAN.

- Измеренный Preview: `dpl_HCxXdMYAvTt8JvYuprwfEBvZECxE`,
  [URL приложения](https://shelf-3cmm35uay-themrack26-1196s-projects.vercel.app).
- `vercel.json`: `regions: ["fra1"]`; поиск — `maxDuration: 180`,
  `/api/health/sources` — `maxDuration: 300`. Значения совпадают с экспортами маршрутов
  и конфигурацией опубликованной сборки из `vercel inspect --json`.
- Фактический `fra1` подтверждён `vercel inspect`, заголовком `X-Shelf-Region`
  во всех 21 ответах и всеми 21 записями `shelf.search`. Сборка происходила в
  `iad1`; место сборки отличается от региона исполнения функций.
- Предварительный API-деплой `dpl_3s9Zso7hzjv1Q2j4FhzT7aZNxTsg` отвечал с `iad1`,
  несмотря на регион в загруженном файле. Он **не включён в выборку**. Измеренный
  Preview создан CLI с явным `--regions fra1`; регион следует проверять после деплоя.
- В Runtime Logs сопоставлены **21/21 идентификаторов запросов**, общие длительности
  и длительности всех источников с JSON-ответами API. Также есть одна намеренная
  проверка невалидного GTIN: HTTP 422, без запросов к источникам; в статистику поиска
  она не включена.
- По фильтрам `error`/`fatal` для измеренного деплоя за окно проверки записей не найдено.
  Все измеренные вызовы завершились HTTP 200, таймаутов функций Vercel в этой серии нет.

Событие `shelf.search` содержит `requestId`, регион, HTTP-код, `elapsedMs`, исход
и статусы/время источников. Пароли, API-ключи, запросы пользователя и URL изображений
не записываются. Успешный ответ также содержит `Server-Timing: search;dur=...`
и `X-Shelf-Request-Id`. При ошибке логируется время от входа в API до ошибки.

## Сравнение рынков на одной партии

Из одного XLSX сделайте два прогона в одной среде и на одной версии сайта.
Первый — в режиме «Молдова». Во втором выберите расширенный поиск и рынок
поставщика. В обоих прогонах отключите сохранённые результаты и задайте одинаковые
настройки веб-поиска. Дождитесь завершения поиска по всем корректным строкам
и скачайте оба ZIP. Скрипт сопоставляет строки по номеру в исходном листе,
поэтому дубли SKU остаются в отчёте.

```powershell
node --import tsx scripts/compare-market-exports.ts UA md.zip ua.zip > review-ua.json
node --import tsx scripts/compare-market-exports.ts UA md.zip ua.zip review-ua.json > comparison-ua.json
```

Перед второй командой заполните `referenceAvailable` для каждой строки по
заранее проверенному наличию доступного эталонного фото. Для первых трёх
кандидатов каждой выдачи укажите в `verdict` один из вариантов.

- `usable_md` — правильный товар, актуальный фронт для Молдовы и есть право использования.
- `wrong_sku` — другой товар, вариант или фасовка.
- `wrong_packaging` — товар верный, но дизайн, язык или рынок упаковки не подходят.
- `unusable` — фото недоступно, не подходит по качеству, либо права или актуальность не подтверждены.

Итог показывает обе выдачи, прирост от выбранного рынка среди первых трёх
кандидатов на 100 учтённых обращений расширенного прогона, ошибки, p50/p95
и знаменатели precision@1 и recall@3. Строки с частичным покрытием и количеством
позиций, для которых зарубежный источник действительно запрашивался, видны в отчёте.
Показатели приведены для всей выборки и для поиска по GTIN и по названию.
