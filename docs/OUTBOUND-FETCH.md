# Исходящие запросы к источникам

Общая политика находится в `src/lib/server/outbound-fetch.ts`:

- `outboundFetch(url, options)` возвращает обычный `Response` для адресов API,
  заданных серверным кодом или конфигурацией.
- Таймаут по умолчанию — **12 000 мс**. `timeoutMs` позволяет сохранить отдельные
  бюджеты источников: probe — 15 секунд, Gemini — 25 секунд.
- `signal` объединяется с таймаутом через `AbortSignal.any`. Уже отменённый запрос
  не отправляется; отмена не отключает таймаут. Дедлайн действует и при чтении тела.
- UA по умолчанию — `ShelfProductImages/0.1 (+https://shelf-img.vercel.app)`.
  Его можно заменить через `userAgent` или заголовок `User-Agent`.
- `Referer` содержит только origin страницы с завершающим `/`. По умолчанию это
  origin целевого URL; для изображения можно передать страницу через `referer`.
  Путь, query, fragment и пароль в Referer не отправляются.
- По умолчанию `cache: 'no-store'`, `redirect: 'error'`. Если relay не настроен,
  ответы возвращаются вызывающему коду без автоматических повторов.

## Один повтор через домашний relay

В окружении приложения задайте `RELAY_URL` (базовый HTTPS-адрес сервиса, без
`/fetch`) и `RELAY_TOKEN` (тот же секрет, что у `infra/relay/`). Например,
`RELAY_URL=https://pc.tailnet.ts.net`. Секрет хранится в `.env.local` или Vercel env.
Для локального приложения разрешён `http://127.0.0.1:8787`; на Vercel loopback
и обычный HTTP не допускаются.

После HTTP **403, 406, 408, 429, 451, 502, 503, 504**, сетевого таймаута или
ошибки соединения (например, `ECONNRESET`) `outboundFetch` делает ровно один
`POST /fetch` с `{"url":"..."}`. Только запросы GET к публичным HTTPS-адресам
без тела и без ключей, cookies или дополнительных служебных заголовков допускают
повтор. POST-запросы поисковых API и Gemini не повторяются.

Прямой запрос и повтор имеют отдельные бюджеты `timeoutMs` (по умолчанию
12 секунд каждый); отмена вызывающего кода прекращает оба. Чтение тела ответа
relay входит в его бюджет и ограничено `maxBytes` (по умолчанию 4 000 000 байт).
Relay не перенаправляет Bearer-токен: перенаправления его endpoint запрещены.

`RelayOfflineError.sourceStatus = 'relay_offline'` проходит через общую
диагностику источников. Этот статус означает ошибку соединения с relay, его
таймаут, неверный токен/адрес или некорректный ответ; детали сокета и секреты
в диагностику не попадают. HTTP-ответ магазина через работающий relay остаётся
ответом магазина, включая 403/429. Ошибки allowlist, размера или таймаута источника
от самого relay сохраняют свой код и отличаются от недоступности сервиса.

`relay: false` отключает повтор. Этот режим установлен для probe и самого
relay-сервера. При настроенном домашнем relay прежний облачный fallback не
запускается следом. Без обеих env-переменных поведение остаётся прежним.

## Публичные URL и места вызова

Для URL, полученных от пользователя, из HTML или выдачи поиска, используйте
существующий `publicGet` из `public-fetch.ts`. Общие проверки URL и DNS находятся
в `public-url.ts` и реэкспортируются из `public-fetch.ts`. `publicGet` вызывает `outboundFetch` с
HTTPS-транспортом, который сохраняет проверку публичного DNS, закрепление IP,
проверку каждого редиректа и лимит размера ответа. Его `signal` отменяет также
ожидание DNS. DNS сохраняет отдельный лимит 8 секунд; таймаут HTTP применяется
к каждой попытке загрузки. Не заменяйте этот путь обычным native fetch.

| Место                                                              | Что запрашивает                                  | Путь                                              |
| ------------------------------------------------------------------ | ------------------------------------------------ | ------------------------------------------------- |
| `search.ts`                                                        | Open Food Facts                                  | `outboundFetch`                                   |
| `catalog-utils.ts`, `regional-search.ts`, `supplemental-search.ts` | Каталоги, OFF и семейство, UPCitemdb             | `publicGet` → `outboundFetch`                     |
| `page-discovery.ts`                                                | Страницы с изображениями                         | `publicGet` → `outboundFetch`                     |
| `discovery-services.ts`                                            | SearXNG, Tavily и другие поисковые API           | Публичный `publicGet` / локальный `outboundFetch` |
| `src/app/api/image/route.ts`                                       | Исходные изображения                             | `publicGet` → `outboundFetch`                     |
| `probe-sources.ts`                                                 | Прямые диагностические запросы и Tavily `/usage` | `outboundFetch`                                   |
| `vision.ts`                                                        | Ручная проверка Gemini                           | `outboundFetch`                                   |

Probe сохраняет прямой доступ без fallback, квот и кэша приложения, чтобы сравнение
домашнего и облачного IP оставалось полезным. Его mock-транспорт тоже проходит
общую политику заголовков, таймаута и отмены.

Проверка границы: `tests/outbound-boundary.test.ts` запрещает использование native
fetch в серверных модулях источников и API. Исключение — уведомление собственного
исполнителя в `cloud-dispatch.ts`; оно не загружает каталоги или картинки.
Браузерные запросы к `/api/*`, локальной ONNX-модели и скрипт установки модели
не относятся к доступу к источникам товаров.

Быстрая проверка: `rg -n '\bfetch\s*\(' src/lib/server src/app/api`.
