# Причины результатов поиска

`SourceStatus` в `src/lib/types.ts` содержит восемь кодов. Диагностика каждого
источника возвращает `status`, `reason`, количество кандидатов и время.
Если известен HTTP-код ошибки, он передаётся в `httpStatus`.

| Код             | Значение                                                                                                         |
| --------------- | ---------------------------------------------------------------------------------------------------------------- |
| `ok`            | Найдены кандидаты; фото ещё требует проверки пользователем.                                                      |
| `empty`         | Источник успешно ответил, подходящих фото нет.                                                                   |
| `blocked`       | Отказ доступа, HTTP-ошибка или невозможность установить соединение. Причина уточняет случай.                     |
| `timeout`       | Истекло время запроса.                                                                                           |
| `quota`         | Ограничение частоты или исчерпание бесплатной квоты.                                                             |
| `parse_error`   | Ответ не удалось разобрать либо источник вернул неверный формат.                                                 |
| `disabled`      | Источник выключен, не настроен или не нужен на текущем шаге каскада.                                             |
| `relay_offline` | Настроенный relay недоступен. Код предусмотрен для подключения relay; обычная ошибка магазина его не выставляет. |

Карточка SKU показывает статус и причину для каждого источника. Ошибка при нуле
изображений остаётся ошибкой, а при частичном успехе найденные фото сохраняются
вместе с причиной сбоя. Ошибки чтения товарных карточек веб-поиска показываются
отдельно от статуса поискового провайдера. Неполный поиск получает результат
`deferred`, а не окончательное «не найдено»; пустой ответ с ошибками не кэшируется.

Общий преобразователь — `src/lib/source-status.ts`. Он также обрабатывает прежние
`unavailable`, `skipped`, `not_configured` и старые сохранённые партии. `message`
сохранён для совместимости и содержит тот же текст, что `reason`. В типе `reason`
необязателен только ради старых данных; новые ответы заполняют его всегда.
Неизвестные исключения получают безопасную общую причину без текста секретов.

CLI probe и `/api/health/sources` используют эти же коды и поле `reason`.
`httpStatus` у probe остаётся фактическим кодом поискового запроса; ошибка
вспомогательной карточки уточняется в причине. Поле `imageCount: null` означает,
что число неизвестно или неприменимо, `0` — успешный пустой ответ.
