# Проверка источников

## Защищённый endpoint

`GET /api/health/sources` возвращает тот же JSON, что и CLI: `generatedAt`,
`referenceEans`, `results`. Общая логика находится в `src/lib/server/probe-sources.ts`.
Endpoint не пишет файлы на сервере и выполняет запросы напрямую с IP среды запуска.
Ответы не кэшируются (`Cache-Control: no-store`). Ошибка одного источника, например
HTTP 403, остаётся в его строке; общий HTTP-статус отчёта — 200.

Доступ — HTTP Basic: пользователь `admin`, пароль из `MVP_ACCESS_PASSWORD`.
Без пароля в настройках endpoint закрыт и в development (503); без корректной
авторизации возвращается 401. Пароли в URL не принимаются. `HEAD` проверяет
только доступ и не запускает источники.

Для сравнения с Vercel:

1. Выполните `npm run probe` локально и сохраните `probe-report.json`.
2. Откройте `https://<deployment>/api/health/sources` в браузере, введите
   `admin` и пароль через Basic Auth и сохраните JSON. Для Vercel Preview может
   дополнительно требоваться вход в Vercel из-за защиты развёртывания.
3. Сопоставьте строки по `source` + `ean`: поле `httpStatus` показывает разницу
   между локальным и облачным IP, в том числе 403. `disabled` означает,
   что переменные сервиса не заданы в этой среде.

В Vercel задайте `MVP_ACCESS_PASSWORD` и нужные переменные источников в выбранной
среде. Используется Node.js и `maxDuration = 300`; тройная проверка EAN с паузами
UPCitemdb может занимать больше обычных 30 секунд. Повторные обращения запускают
новую проверку; одновременно допускается до трёх работ внутри процесса через
существующий `boundedWork`. На бесплатном Hobby с Fluid Compute доступны
[300 секунд выполнения](https://vercel.com/docs/functions/configuring-functions/duration).
Платные сервисы probe не вызывает.

## CLI

Запуск из корня проекта: `npm run probe` (Node.js 24, зависимости установлены).
Команда печатает таблицу и перезаписывает `probe-report.json` в текущей папке.
Отчёт исключён из Git. Ошибки отдельных источников сохраняются в отчёте и не
прерывают проверку; ошибка записи отчёта завершает команду с кодом 1.

Для METRO MD, Bonus, Linella, Bucuria, Open Food Facts, Open Beauty Facts,
Open Products Facts, Open Pet Food Facts, UPCitemdb и SearXNG выполняется
поиск по каждому из трёх EAN:

- `4840053004404` — JLC (эталон из тестов проекта).
- `4600699006831` — Слобода (эталон из проверки очереди).
- `3017620422003` — Nutella.

Tavily проверяется **одним GET `/usage` на запуск**: этот запрос относится
к аккаунту, а не к EAN, и изображений не возвращает. `/search`, `/extract`
и другие расходующие поисковую квоту методы Tavily не вызываются.
[Контракт Tavily](https://docs.tavily.com/documentation/api-reference/endpoint/usage).

Дополнительные настройки берутся из окружения и необязательного `.env.local`:

```dotenv
SEARXNG_URL=http://127.0.0.1:8080
SEARXNG_API_TOKEN=
TAVILY_API_KEY=
OPENFOODFACTS_USER_AGENT=
```

SearXNG должен разрешать JSON-выдачу. Используется `/search?format=json&categories=images`;
локальный сервер допустим. [Контракт SearXNG](https://docs.searxng.org/dev/search_api.html).
Без адреса SearXNG или ключа Tavily соответствующие строки получают
`disabled`, HTTP и число изображений — `null`.

Строки содержат источник, EAN, фактический HTTP-статус, время в миллисекундах,
число уникальных изображений и результат: `ok`, `empty`, `blocked`,
`timeout`, `quota`, `parse_error`, `disabled`, `relay_offline`. Поле `reason`
объясняет результат; [единые коды причин](SOURCE-STATUS.md).
Ноль означает успешно разобранный ответ без изображений; `null` — число
неизвестно или неприменимо. HTTP сохраняется и при ошибке разбора тела.
Для Tavily сохраняются только поля тарифа и использования, без ключей и сырых ответов.

Каталоги используют существующие парсеры проекта. У Linella считаются миниатюры
товаров в поисковой выдаче. У Bucuria читаются до трёх карточек найденных товаров;
ошибка карточки указана в примечании, HTTP в строке относится к поисковой странице.
Счётчик показывает доступные изображения кандидатов, не подтверждает правильность
товара, бренд или фасовку. Парсеры GTIN не ослабляются.

Проверка идёт напрямую с IP машины запуска, без кэша, relay, БД и circuit breaker.
Источники проверяются параллельно, EAN внутри источника — последовательно.
Запросы к одному хосту выдерживают паузу: UPCitemdb — 10 секунд,
семейство OFF — 4,1 секунды, Zakaz — 0,8 секунды, остальные — 1 секунду.
Повторов нет. Таймаут одного запроса — 15 секунд, предел тела — 2 МБ.
Время строки включает ожидание ограничения частоты и чтение карточек Bucuria.
Один запуск расходует три бесплатных запроса UPCitemdb; частые повторные запуски
могут исчерпать дневную квоту. Отчёт отражает только доступность в месте запуска.
