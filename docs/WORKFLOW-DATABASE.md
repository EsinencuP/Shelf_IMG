# Общий каталог и фоновый поиск

Для Shelf выбран Neon Free: отдельный проект `shelf-workflow-db` (`dawn-base-40979595`), Frankfurt, PostgreSQL 18. Он подключён к `shelf-img` через Vercel Marketplace. Дополнительные сервисы Supabase Auth/Storage сейчас не нужны; существующая защита паролем сохранена.

## Работа

1. Откройте сайт Vercel и запустите поиск. Облачная функция `shelfsearch` в Neon Free включается автоматически. Запускать приложение или worker на компьютере не нужно.
2. Загрузите Excel или добавьте один артикул. Сайт сохраняет задания в очередь; после закрытия вкладки worker продолжает работу.
3. После возвращения на сайт откройте ту же партию в том же браузере. Идентификаторы заданий хранятся в IndexedDB; результаты подтягиваются из общей базы. Для защищённого API при необходимости снова введите пароль.
4. Проверьте фото и подготовьте JPEG. Подтверждение для экспорта также сохраняет фото в общий каталог. Следующие запросы этого EAN используют каталог до обращения в интернет. Без EAN ключ включает оба названия, бренд и фасовку. Сохранение в каталог не заменяет проверку актуальности упаковки.

Схема: браузер → Vercel API → очередь PostgreSQL → Neon Functions → результат в PostgreSQL. Vercel отправляет короткий защищённый сигнал запуска. Функция подтверждает его и выполняет ограниченный проход очереди через `waitUntil`, до 8 минут плюс текущий поиск (предел Neon — 15 минут). При большой партии следующий проход запускается автоматически. Общая аренда допускает одного облачного исполнителя; после сбоя аренда истекает через две минуты. Опрос статусов повторяет сигнал запуска для ожидающих заданий, а ежечасный Neon Trigger восстанавливает очередь даже при закрытом браузере. В норме поиск начинается сразу; после аварии без открытого сайта восстановление может занять до часа.

Когда заданий нет, функция завершает вызов и не опрашивает базу постоянно. Ежечасная проверка расходует небольшую часть бесплатной квоты. Neon Free включает 1 млн вызовов, 10 часов активных и 400 часов ожидающих вычислений Functions в месяц; PostgreSQL — 100 CU-часов на проект. Квоты конечны: при их исчерпании сервис может приостановиться. Платный план не включается. [Актуальные условия Neon](https://neon.com/docs/introduction/plans).

Excel, обработка фона/JPEG и ZIP выполняются в браузере: для них нужен открытый сайт, но не локальная установка. Эти операции пока не продолжаются после закрытия вкладки. Для отладки оставлен запасной `npm run worker`; одновременно с облаком его запускать не нужно.

Явный «Повторить поиск» и отключённый параметр сохранённых результатов обходят общий каталог: это позволяет найти новую версию упаковки. При первом быстром запуске форма ждёт конфигурацию сервера, чтобы не обходить очередь из-за задержки загрузки страницы.

## Настройка

Секреты только на сервере: `DATABASE_URL` — pooled, `DATABASE_URL_UNPOOLED` — direct для миграций; `SHELF_WORKER_URL` и случайный `SHELF_WORKER_SECRET` — в Vercel и Neon Function. Функция сравнивает секрет до обращения к базе. Путь `/cron` принимает только подтверждённые доставки Neon Trigger; поддельные клиентские заголовки Neon удаляет. Neon проверяет TLS-сертификат (`verify-full`). Миграция хранится в `migrations/001_workflow.sql`; запуск `npm run db:migrate`. Сначала проверять на отдельной ветке Neon, затем на основной. Скрипт добавляет таблицы и индексы, не удаляет существующие данные.

Исходник функции — `functions/search-worker.ts`, сборка ZIP — `npm run worker:build`. Развёртывание через Neon MCP `deploy_function` (ZIP + серверные переменные) или Neon CLI `functions deploy`. Ключи Brave/Tavily передаются только функции и защищены прежними ограничениями бесплатного расхода. Gemini автоматически не используется. Для облака действуют те же ограничения сайтов: HTTP 403 не гарантированно устраняется переносом исполнителя; публичные карточки дополнительно читаются Tavily Extract, поиск продолжает каскад и сохраняет неоднозначные совпадения для проверки.

`shelf_library`: подтверждённая идентичность, источник/лицензия, JPEG и миниатюра. Фото до 2 МБ; каталог ограничен 200 МБ, повтор одинакового фото не увеличивает объём. При отказе базы подтверждение для локального экспорта остаётся доступным, но UI сообщает, что общий каталог не пополнен.

`shelf_jobs` хранит запрос, результат, ключ идемпотентности, номер попытки, время повтора и аренду. Исполнитель получает задание атомарно с `FOR UPDATE SKIP LOCKED`. После истечения аренды задание может взять другой исполнитель. Отменённое задание прерывает внешние запросы при следующей проверке аренды, обычно в течение 15 секунд. Просроченная или отменённая аренда запрещает запись итога.

Одна попытка поиска ограничена 90 секундами, включая ожидание очереди источника, DNS и загрузку. По истечении лимита сохраняются найденные кандидаты и диагностика неполного поиска. Повтор при временном сбое учитывает паузу источника и ограничен тремя попытками.

`shelf_source_slots`: общие интервалы для каталогов, OFF, Brave и Tavily. Это ограничение частоты запросов, не гарантия общей месячной квоты. Brave должен иметь provider usage limit Free, Tavily — отключённый Pay-as-you-go. Платные планы не включались. Для Neon Free не требуется upgrade; актуальные ограничения смотрите в [кабинете ресурса](https://vercel.com/themrack26-1196s-projects/~/integrations/neon/icfg_rX8g6BZYAb0qQTFpXCwe7zuJ/resources/storage/store_ZVTi2XmfRhjtFXWe/guides).

API каталога и очереди используют существующий пароль доступа, ограничения размера и проверку origin. Это один общий рабочий кабинет, не многопользовательская система с tenant isolation. Оригиналы и история всех партий не синхронизируются между браузерами; подтверждённые фотографии и результаты заданий доступны через базу.

## Проверки

`npm run typecheck`, `npm run test`, `npm run test:e2e`, `npm run build`.

`scripts/check-database.ts` запускается только с `DATABASE_INTEGRATION_URL` от изолированной ветки. Проверяет повторную отправку, параллельный захват, отмену, восстановление аренды, отказ записи старого worker, отложенный повтор и общий каталог. Тестовые записи остаются только на этой проверочной ветке.

`scripts/check-cloud-worker.ts` использует gitignored `.runtime/cloud-test.json` с `DATABASE_INTEGRATION_URL` и `SHELF_WORKER_URL` изолированной ветки и секрет из `.env.local`. Проверяет отсутствие анонимного доступа, отбрасывание поддельного cron и выполнение двух заданий целиком в облаке.
